PDF 里的隐藏文字，大多数不是故意藏的。它们是从源文档带过来的残留：被图片盖住的一段话、白色形状上的一行白字、被拖到画布外的文本框、没人处理掉的批注。这些东西都不会显示在页面上，而它们全都在你刚刚发出去的那个文件里。

这件事比过去更要紧。一份合同、一份报告、一份方案，现在经常会经过某个读文本层而不是看页面的程序：摘要工具、搜索索引、审阅助手、尽调系统。你导出时留下的一切，都会被它们完整读到。

## 它们从哪来

**被不透明的东西盖住的文字。** 在一段话上面放一张图片、一个填充矩形或者一个白色方块，视觉上它消失了，文本层什么也没变。字符还在，还能被提取，还保持着阅读顺序。这是导出的 PDF 里最常见的意外文本来源，因为它看起来像删除，其实不是。

**白色或近白色的填充。** 白页上的白字，或者白底上的浅灰字，在正常阅读距离下看不见，却完整地存在着。有时候这是故意的，更多时候是模板留下的，或者某段文字被高亮过、后来取消了高亮，字体颜色却留在了白色。

**被挪到页面外的对象。** 在 Word 和 Google Docs 里，浮动的文本框或图片可以被拖到页面边界之外。它不再被渲染，但它没有不再存在。设计工具在这方面更严重：一份 Canva 或 Figma 的简历模板，可能把整整一层画布外的说明文字带进导出结果。

**Word 的隐藏文字属性。** Word 有一个把文字标记为隐藏的字体效果。默认情况下它不会被打印，也不会进入 PDF 导出，所以这一项通常表现符合预期。例外是「打印隐藏文字」这个选项：把它打开再导出，你特意隐藏的文字就在 PDF 里了。如果你用这个属性在草稿里留笔记，导出定稿之前先确认一下这个设置。

**修订记录、批注和演讲者备注。** 修订状态下被删除的文字、未解决的批注，以及文档元数据（作者、公司、之前的文件名），会不会留在导出结果里，取决于导出时的设置。Google Docs 的建议模式同理，如果导出时建议既没被接受也没被拒绝，它们会跟着走。

**没有正确嵌入的字体。** 偶尔会出现这种情况：导出后的文字渲染成空白或者错乱的字形，而底层字符在文本层里完全正确。页面看起来是坏的，提取出来的文本却是好的。反过来的情况也存在，这也是把两者对照一遍值得做的原因。

## 发出去之前怎么找

这项检查不到一分钟，什么都不用装。

**全选并复制。** 打开导出的 PDF，按 Ctrl/Cmd+A，复制，粘贴到纯文本编辑器里，然后读一遍。凡是在编辑器里出现、你却在页面上找不到的内容，就是隐藏文字。这一步能同时抓到被盖住的文字、白色文字和大部分页面外的对象。

**比对篇幅。** 对长文档，把提取出来的文本粘进字数统计工具，和源文档的字数比一比。任何一个方向上的大幅差距都值得解释。

**做一次结构扫描。** 复制粘贴有实实在在的局限：它通常读不到关闭状态图层里的文字，也不会告诉你嵌入文件、JavaScript 或注释内容的情况。[本站的扫描器](/)读的是文件结构而不是渲染后的页面，它会报告近白色文字、不可见渲染模式、极小字号、页外文字、裁剪框不一致、隐藏图层、注释、嵌入文件和嵌入 JavaScript，每一条都带页码和原文。它在你的浏览器里运行，所以一份保密的草稿不会被上传到任何地方。

这套检查更完整的手工版本，包括 `pdftotext` 的用法和怎么手动打开隐藏图层，见[如何检查一个 PDF 里有没有隐藏文字](/learn/how-to-check-a-pdf-for-hidden-text)。

## 怎么才算真的删掉了

找出来是容易的部分。真正删干净意味着回到源文档去改，因为 PDF 是产物，直接改产物往往只是换了一种方式把文字藏起来。

- **删掉，不要盖住。** 在源文件里把那段话删掉，而不是在上面压一个形状。
- **导出前处理掉修订记录**，接受或拒绝所有修订，解决或删除批注。
- **检查画布外的对象。** 在 Word 里，选择窗格会列出页面上的每一个浮动对象，包括你看不见的那些。在 Google Docs 里，切到打印布局再翻一遍页边距，通常就能发现它们。
- **导出时顺手清掉元数据**，前提是收件方并不需要它。多数导出对话框里都有「文档属性」或「删除个人信息」之类的选项。
- **重新导出，重新检查一遍。** 这项检查的意义就在于它便宜到可以做两次。

如果你回不到源文档，比如别人发给你一个 PDF，而你需要一个干净的版本，那么把页面栅格化会连同隐藏文字一起去掉所有文本层，代价是文档不再可搜索，屏幕阅读器也读不了。这笔交易很少划算。修源文件才划算。

## 「干净」意味着什么

结构扫描结果干净，意味着这个文件的文本层和结构里，没有你不打算发出去的东西。它不意味着这份文档在更广的意义上是安全的：烤进图片里的文字按设计就不在这类检查的范围内，靠版式而不是字符传达的信息同样如此。它真正告诉你的是，机器读到的那个版本和人读到的那个版本是同一份文档。对于你即将签署、提交或者发给客户的东西，这正是你想要的那个性质。
